Analytics Console Overview

The Analytics Console lets you view OpenEvolve checkpoints, latest metrics, log activity, and configuration values in one dashboard. It is designed to keep operational data visible while OpenEvolve is running simultaneously.

The interface supports multiple pages that share the same left-hand navigation and styling so movement between dashboard, documentation, mLLM, and settings stays consistent.

  • View current dashboard metrics and charts
  • Inspect OpenEvolve logs and checkpoint activity
  • Review configuration values used by the console
  • Change source paths from the settings page
  • Documentation to allow users understand how to use the console

Data Flow

The dashboard reads from backend endpoints that expose OpenEvolve checkpoint data, config summary data, and the latest available log file. The frontend polls these sources and renders updated values into the panels and charts inside the Dashboard page.

/openevolve/examples/problem_destination/problem_output/checkpoints # this is a directory path /openevolve/examples/problem_destination/problem_output/logs # this is a directory path /openevolve/examples/problem_destination/config.yaml # this is pointing it directly to the config.yaml file

Dashboard Panels

The main dashboard is divided into two regions; outside and inside panels. This layout keeps the most important chart area large while secondary operational details stay visible around it.

Primary center panels

The center panels contains the main performance chart and any secondary metric cards that are generated from the evaluation file created by the user, The data being passed through in this region is from the latest checkpoint directory that OpenEvolve creates.

Operational outside panels

The side panels contains supporting information like configuration set up, latest metric values, log activity, and system logs.

OpenEvolve Sources

OpenEvolve data is typically pulled from three places: checkpoint folders, the YAML configuration file, and the logs directory. These sources can be updated from the settings page so the console can point to a different environments of wherever OpenEvolve is being run.

Configuration

The configuration panel displays values like max iterations, checkpoint interval, population size, and number of islands. These are read from the configured YAML file path. This showcases how the OpenEvolve run is configured.

Logs

The OpenEvolve Log panel shows the latest log file contents used in OpenEvolve which is often showcased on the terminal when running, while the System Log panel shows frontend activity and polling status. Keeping both visible makes it easier to separate backend output from dashboard behavior.

mLLM

The mLLM page provides access to the console’s chatbot-style interface. From this page, users can interact with the model, code generate OpenEvolve intial programs and evaluator scripts, review workflow, and ask what metrics can be used in problems. This model is a mini language model that is trained on OpenEvolve example problems, code, and generalized data. Most importantly this model can be fine-tuned over time to better support uncorrelated track processing algorithms as newer algorithms are developed in OpenEvolve's AI architecture.

This model is based off of Andej Karpathy's nanochat, which is an experimental harness for training LLMs. This local model can be trained for only 2 hours using 8XH100 GPU nodes for 48-100 dollars to reach gpt 2.0 benchmarks.

3DViewer [ALPHA]

The 3DViewer page provides a dedicated visualization environment for orbital and track-based data. This page is intended to help users inspect spatial relationships between Earth, reference objects, observations, and UCT output in an interactive scene.

Users can rotate, zoom, and switch between supported display modes to better understand how grouped observations relate to reference tracks and generated outputs from UCTP. The page is especially useful for visually validating whether clustering, grouping, or state-vector generation results align with expected geometry.

  • Displays a 3D Earth-centered scene for track visualization
  • Supports modes such as OBS, REF, UCT Output, and Compare
  • Allows users to inspect grouped objects and related details
  • Supports changing dataset paths for alternate JSON-based runs
  • Acts as an alpha environment for future 3D SDA analytics features

Page Navigation

Every page uses the same left sidebar. From here you can move between:

  • Welcome: Front page before entering the Analytics Console
  • Dashboard: Main analytics page which showcases OpenEvolve real-time evolutions, OpenEvolve configuration set ups, OpenEvolve most recent logs, and data pulling metrics.
  • 3DViewer: Page for visualizing 3D models and data, currently in alpha testing.
  • mLLM: Model that can help the user better understand the Analytic Console workflows or help generate OpenEvolve required codes such as initial programs and evaluator files based off different algorithms.
  • Documentation: This page provides detailed information about using the OpenEvolve Analytics Console.
  • Settings: Page for configuring the OpenEvolve Analytics Console settings on how the data is being pulled from different environments and directories.

Best Practices

Keep the settings paths updated to the correct checkpoint, config, and logs directories before using the console in a new environment. This avoids mismatched charts, missing config values, or stale log data.

Recommended workflow: 1. Set checkpoint path in Settings 2. Set config YAML path in Settings 3. Set OpenEvolve logs path in Settings 4. Return to Dashboard 5. Confirm metrics, config values, and logs are updating 6. Run your algorithm evolution
